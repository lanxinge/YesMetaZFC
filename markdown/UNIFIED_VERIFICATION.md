# 证明边界与构建入口

本页说明对象理论、Lean 元层证明和构建结果之间的区别。具体定理与数学前提见
[TROPHIES.md](TROPHIES.md)，模块使用方式见 [ENGINEERING.md](ENGINEERING.md)。

## 全源构建

```text
lake --wfail build
python scripts/lean_cache.py build
python scripts/lean_cache.py build --native
```

第一条构建公共入口；第二条直接枚举当前全部 Lean 源文件，包含未被公共入口导入的独立模块；
第三条同时构建全部原生对象、静态库和共享库。CI 使用第三条命令。
模块移动、合并及新增不需要维护另一份注册表。

构建成功表示相应源码经过 Lean 编译和内核检查。公开接口的前提强度、数学定义与目标的对应，
仍以源码中的实际声明和证明为准。旧模块数量、固定端点清单和历史运行结果不作为当前提交的门禁。

## 当前 Lean 公理边界

区分以下三个层次：

| 层次 | 含义 |
| --- | --- |
| Lean 元层 | 证明项及其对 `propext`、`Quot.sound`、`Classical.choice` 等声明的依赖 |
| 对象理论 | 原一阶语言中的 KP、ZF、ZFC 等理论；定理由实际模型前提或 `Derives` 前提约束 |
| 内模型 | 固定结构中的相对载体及其满足关系，如规范 L(ℝ) 和泛型扩张 |

宿主证明在 `Prop` 内使用经典推理，不等于假设对象模型满足选择公理。
另一方面，命题中的存在证明也不能直接当作已经给出的 `Type` 层对象或选择函数。
数据、解释映射与模型构造的实例必须由代码实际实现。

项目不通过新增公理或虚空参数填补数学缺口；缺口只能显式使用 `sorry`。
`lake --wfail build` 会拒绝带有相应警告的构建。不得通过加强前提或改变定义来掩盖未完成的证明。

`sentence!` 的透明闭合性输入优先走内核计算，opaque 输入仍有 `native_decide` 后备分支。
一个具体声明的依赖不能仅由宏名推断。需要核对指定端点时，可在临时文件中使用
`#print axioms`，并结合声明类型和定义体阅读；不将临时探针纳入生产导入图。

## 模型、公理与推导

`M.Models Γ` 是指定语义下的模型性，`Derives Γ φ` 是原推导核中的句法结论。
模型语义证明不会自动产生某个指定编码的对象证明；从相对模型得到外部模型也需要实际传输定理。
模型载体、变量排序、解释与自由参数环境应在各接口中保持明确。

内部 ω 不要求在外部标准或良基。内部归纳必须作用于已能由原对象语言表达的性质，
不能把背景中的任意额外谓词直接交给纯分离或归纳模式。

用于大基数终点的源模型、扩展器、返回图、泛型与策略都由原数学前提实际构造。
弱测试壳只承担有限反射及有界证书，不被额外赋予完整 ZF。

## 连续集成与缓存

五个平台执行相同的全源与原生构建。成功编译后立即保存增量缓存，再生成并实际恢复
Lean 与完整原生归档。全部平台通过后，主分支发布同一提交的完整缓存集合。
流程及下载方法见 [CACHE.md](CACHE.md)。

缓存工具的 Python 测试检查归档、恢复和发布行为，不枚举数学样本，也不另造证明前提。
已移除静态模块清单、公理依赖白名单、配套守卫测试及旧审计快照。
构建源码由实际文件枚举，数学边界由实际声明表达。

## 维护

失败时先区分工具链启动、Lean 编译、原生链接、缓存打包、恢复或发布步骤。
修复针对实际失败日志，不通过关闭真实构建、跳过独立模块或伪造成功状态完成。
发生源码改变后运行受影响模块及必要的全源构建；历史计数和旧日志不替代当前结果。
