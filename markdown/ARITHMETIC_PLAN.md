## 复用决策

- 主要来源：旧 BMS 工作副本的 SecondOrder 与 Primitive 文件。保留 Apache-2.0 署名和来源哈希，
  重建最小签名，删除 `pair/start/step` 等 BMS 专用原语和对应语言布尔 guard。
- 数码运算下降到 Q；数目公式的归纳／内部编码下降到 PA；集合参数接口保留 Z₂。
  这是真正更换证明依赖，不是删除假设或改名。
- 图公式、宿主函数、标准正确性和任意模型证书分开。共有两个实际消费者时提取通用模板，
  不为抽象而另造逻辑 AST、模型类型类或证明核。
- 直接复用上游类型化 AST、替换、推导、可靠性和 Henkin 完备性。
  可选完备性只消费所有模型真值，不使用标准模型真值反射。
- 1Y、FullMarkedBLP、RankElementarity、IBLP、PCF 等只作接口／证明组织参考；
  没有把它们的集合论或 Mathlib 依赖装入算术核心。
- 不修改旧 BMS 仓库，不重启 BMS 良序性、第三阶背景或等一致性研究。

## 维护和验收流程

规范优先读 [AGENTS](AGENTS.md)、[ProofNaming](ProofNaming.md)、
[ENGINEERING](ENGINEERING.md)、[RESTORE](RESTORE.md) 和
[模型目录指南](../YesMetaZFC/Model/README.md)。

1. 确认当前分支、未提交变化和上游基点；构建按同一工具链串行执行，避免共享产物竞态。
2. 先核对声明合同：理论、排序、变量槽、量词、局部上下文、guard、内部／外部自然数。
   任意宿主谓词不能直接获得对象归纳，内部数不默认标准或外部良基。
3. 小批可逆改动，先构建相关入口和可选模块，再做公理审计及外部调用验证。
   不维护只有重复调用作用的永久 example 文件；失败证据留在库外。
4. 控制单文件低于 2,000 行、未提交改动低于 3,000 行；保持可读注释，
   不通过压行数、更强假设、新公理、占位证明或额外原生可信计算精简。
5. 完整验收使用全源／原生构建及算术公理审计，
   不能用局部绿色代替全仓 CI；公理枚举必须覆盖可选模块并核对源码指纹。
6. 模块分层与命名按主判断：宿主数据／计算 `_l`，语法／元理论／对象推导 `_m`；
   不照抄旧长命名空间，不用 helper/aux/tmp/new/v2 作公共数学名。
7. 用户要求剩余成果全部完成后一次性更新 PR。本地可分批验证提交；
   不直接推送上游 main，不自行合并，不以额外“等待审查”文档替代正常 PR 流程。
