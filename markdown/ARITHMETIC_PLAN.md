## 3. 为什么不能整目录迁移

旧 `SecondOrderSyntax` 除 `0,S,+,×,∈` 外还有 `pair/start/step`，标准解释导入 BMS 的
起点、展开和译码。新语言必须从类型上排除这些专用符号；配对作为可定义关系／定义扩张另行提供。
旧纯语言检查中为屏蔽 BMS 符号而存在的分支应删除，而不是保留永久的 `hφ : language φ = true` 负担。

按实际导入边追踪，仅统计旧桥目录内的闭包，含目标文件：

| 目标文件 | 旧桥闭包模块数 | 旧桥闭包行数 |
| --- | ---: | ---: |
| `SecondOrderArithmetic` | 9 | 2,144 |
| `SecondOrderModel` | 11 | 2,359 |
| `SecondOrderBetaSequence` | 44 | 7,145 |
| `SecondOrderProgramTotality` | 49 | 8,531 |

以上闭包均还含外部导入；8,531 不是完整依赖行数，也不是拟迁移行数。
总性闭包触及 `YesMetaZFC.BMS.WellFoundedness` 等模块和 Mathlib 的配对、β 函数、原始递归及代数工具。
导入污染本身不证明其数学内容依赖 BMS 良序性；必须拆除后由新构建和声明依赖审计确认。

## 5. 精确数学合同

### PA

使用独立单排序语言，Q 由后继非零、单射、非零数有前驱、加法零／后继、乘法零／后继七条组成。
PA 定义为 Q 加全部算术公式的归纳模式，参数全称闭包显式实现。
归纳模式从实际 `φ(x,p̄)` 生成，不能给模型载体加“任意 Lean 谓词的归纳”字段。
若与不单列前驱公理的常用 PA 呈现比较，另证相互公理可推导，不靠注释宣布定义相同。

第一组验收命题（数学规格，非已可调用的 Lean 声明）：

- 任意算术公式 φ 和任意有限数目参数，`PA ⊢ Ind(φ)`。
- 局部上下文 Γ 中的基例与归纳步可推出全称结论；新增变量对 Γ 的新鲜性明确。
- `Q ⊢ n̄ + m̄ = (n+m)̄`、`Q ⊢ n̄ × m̄ = (n*m)̄`，以及不同数码不等。
- 实际构造标准自然数模型，逐条证明模型性，由已有可靠性得到元层一致性。

### Z₂

两排序为数与数集；数目函数仅 `0,S,+,×`，唯一非逻辑关系为成员。
以逻辑等号和集合外延性处理数集等同，七条数目基础加集合归纳。
完整理解允许公式含任意数／集量词，以及任意有限混合参数；新见证集合不得在原公式中自由出现：

`Z₂ ⊢ ∀p̄ ∃X ∀n (n ∈ X ↔ φ(n,p̄))`。

验收须包含：完整理解模式、由其导出全公式归纳、标准 `(Nat, Nat → Prop)` 模型、PA 数域约化、
PA 推导向 Z₂ 的翻译保持。翻译要覆盖项、公式、上下文、代入、逻辑规则及公理像。
这只说明扩张／解释关系，绝不说明 Z₂ 对 PA 保守。
如果将来接 Full 二阶 AST，另写公式翻译与逐式语义对应；本阶段不要求该桥。

### 编码与递归

必须分开四种交付：宿主 Nat 上计算正确、标准模型表示正确、任意非标准模型内部总性、对象理论可推导总性。
`∀ c : Program` 的外部有限语法归纳不等于模型内部所有程序码的统一全称断言。
β 编码中的长度若是模型内部自然数，不得换成宿主 `Nat` 或宿主有限列表。
旧 `beta_sequence_l` 还量化内部数集 H；若降到 PA，必须改用算术可定义图／数码，不能只删除集合假设。
旧内部图总性首先保留为 Z₂ 的迁移目标；PA 中每个给定原始递归程序的表示与总性单独建设。

## 6. 签名优化和命名规则

每个迁移声明先登记“原结论／原假设／新结论／新假设／层级／消费者／证据”，再改代码。

| 原接口问题 | 新接口要求 |
| --- | --- |
| 数码运算一律要求 Z₂ | 先给 Q 基础证明，经理论包含／推导弱化复用 |
| 一般数域恒等式一律要求 Z₂ | 审查实际归纳公式；数目公式下降到 PA |
| `language_m φ = true` 用于排除 BMS 扩张符号 | 最小签名消除该条件；真正的算术层级判定另有名称 |
| 一个 graph 结构同时绑定宿主 `Nat → Nat` 与任意模型解释 | 拆分语法图、标准正确性证书、任意模型关系／总性证书 |
| 到处重复 zero/succ/add/mul 和参数列重排 | 共享 Syntax 操作，复用替换代数与环境映射 |
| 模型结构／理论满足混成全局实例 | 任意结构与显式 `hℳ : Models ℳ T` 分开；仅局部能力按需实例化 |
| 闭句专用、数值参数硬编码 | 尽量保留任意合法 Γ、Δ、环境与 universe；从通用定理专门化 |

声明只能有一个终止层后缀：宿主计算／数据 `_l`；语法、理论、推导与元层对应 `_m`；
对象理论内部判断 `_d`。不能按目录或“用了 simp”机械决定，也不能照抄旧桥后缀。
例如 `PA.theory_m`、`Z2.comprehension_m`、`PA.numeral_add_m`（结论为 Derives）是候选名称；
具体类型确定后按 ProofNaming 复审。纯模型载体运算和跨层满足对应须分别判层。
命名空间携带主题，不再保留 `YesMetaZFC.BMS.ConstructibleBridge` 长前缀。
不用 `helper/aux/tmp/new/v2/final` 作公共数学名；短数学变量、`hφ/hΓ/hPA/hZ₂`，中文数学注释。
纯集合语言保留 `ℒ`；算术或任意语言用 `σ` 等不冲突符号。

## 8. Agent 工作循环与检验

每个小任务依次执行：

1. 读本计划及上游指引；检查 HEAD、工作区差异、现有正在构建的进程和广场状态。
2. 先写数学合同，查上游已有声明及实际类型；只读取本任务的依赖锥，不重扫所有旧工程。
3. 记录 donor 文件哈希与拟改签名；逐模块实现，不一次搬入整个依赖闭包。
4. 使用 `prove_auto` 及通用替换／推导接口；不另造证明核，不依赖旧 tactic 名称。
5. 单模块构建，然后实际消费者构建；语义审查与编译审查分别登记。
6. 更新来源表、关键出口、真实日志与下一项合同。验证后的贡献按已授权的 fork／PR 流程提交。

默认保守使用 `LEAN_NUM_THREADS=1`；同一工作树只有一个构建者，不与旧工具链共享 `.lake/build`。
若以后多 agent 并行：按模块指定唯一写者，先冻结公共签名，再分支工作；不得同时改聚合入口和底层签名。
单模块超一分钟按上游工程指南定位原因，禁止靠扩大心跳掩盖失控展开。
遵守上游单文件不超过 2,000 行、未提交增量不超过 3,000 行等门槛；到提交边界先验收当前批次，再提交独立贡献分支。

验收命令按实际创建的模块名运行；未创建的名字不能作为成功记录：

```text
lake --wfail build <本次模块> <直接消费者>
lake --wfail build
python scripts/lean_cache.py build --library-only
python scripts/lean_cache.py build --native
```

前两级为局部及库构建；全源与 native 按准备发布的范围执行，不能把局部绿色称为全仓 CI。
全源入口还可用 `bash scripts/check-all.sh --library-only`，以当前脚本实际行为为准。
禁止同一缓存交替用 v4.33.1 与 rc1；缓存命中不替代源码变更后的构建。

静态筛查新增源码中的 sorry/admit、自定义 axiom、公理逃逸、native_decide、关闭 linter 和无限制资源设置。
文档提及禁止词不构成代码违规；静态扫描也不能代替内核依赖审计。
关键新增公开出口运行 `#print axioms`，记录来源 SHA、命令、退出码和日志。

不要因为上游某些无关模块已有其他信任依赖，便声称算术核心可以继承而不审查。
