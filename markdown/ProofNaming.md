# 证明命名规范

本规范约束 YesMetaZFC 中的公开定理、引理、可调用证明定义，以及直接服务于证明接口的公开定义和谓词。

仓库的证明架构分为三层：

1. Lean 宿主层
2. 对象元理论层
3. 对象理论层

命名必须让调用者能够在不展开模块路径的情况下识别命题所属层，同时尽量保持数学记号的密度。

## 一、层标记

### 1.1 唯一层后缀

层级只使用一个末尾后缀表示：

| 后缀 | 含义 |
| --- | --- |
| `_l` | Lean 宿主层（Lean host） |
| `_m` | 对象元理论层（meta） |
| `_d` | 对象理论层（deep） |

公开命题接口的基本形式为：

```text
<数学词根>_<层>
```

例如：

```text
wff_m
subst_m
subst_wff_m
derives_m
sound_m

sat_d
pair_d
ext_d
infinite_d

map_l
ext_l
congr_l
```

层标记必须满足以下约束：

- 层标记只能出现一次；
- 层标记必须位于名称末尾；
- 不使用 `lean_`、`meta_`、`deep_` 等层级前缀；
- 不使用 `_lm`、`_md`、`_l_m` 等多层组合后缀；
- 不因为证明依赖了另一层就改变当前命题的层标记；
- 以命题主结论所属的判断或对外接口所属层作为归属依据。

源码统一采用 ASCII 形式 `_l`、`_m`、`_d`，不在同一个命名系统中混用 Unicode 下标字形。文档和数学注释可以将其排版理解为右下角层下标。

### 1.2 三层的判定原则

层标记描述命题的数学归属，不描述证明脚本使用了什么 tactic，也不单纯由文件所在目录决定。

#### `_l`

主结论针对 Lean 宿主对象、Lean 数据结构、宿主函数或宿主证明基础设施。

典型内容包括：

- Lean 原生数据结构的性质；
- 递归函数、映射、编码器和检查器的宿主层性质；
- 与对象理论无关的宿主层等式、同构和同余定理。

#### `_m`

主结论针对对象元理论对象及其判断。

典型内容包括：

- 项、公式、上下文、理论和推导；
- 语法变换、替换、重命名、范式化；
- `Derives`、证明证书、元层可靠性和完备性；
- 面向对象理论的编码、解释和元层检查器。

#### `_d`

主结论针对对象理论内部对象或对象理论自身的判断。

典型内容包括：

- 对象理论内部的集合、序数、基数和模型对象；
- 对象理论公理及其内部推理；
- 对象理论层的外延性、配对、无穷性等性质。

### 1.3 跨层命题

跨层定理仍然只允许一个层后缀，不得制造双层名称。

命名时按以下顺序判定：

1. 看主结论最外层的判断；
2. 若是桥接定理，看它服务的公开调用接口；
3. 若仍有歧义，归入拥有该判断定义的层；
4. 在文档或定理注释中说明另一层，不把说明塞入名称。

例如，元层的推导可靠性接口命名为 `sound_m`，即使其结论涉及对象理论层的满足关系，也不写成 `sound_md`。

## 二、数学词根

命题名只表达数学内容，不表达证明过程。

推荐使用短而稳定的数学词根：

```text
wff          良构公式
wf           良构对象
closed       闭
free         自由变量
fv           自由变量集合
bv           绑定变量
subst        替换
rename       重命名
eval         求值
sat          满足
derives      可导出
ax           公理
imp          蕴含或 MP
gen          全域化
cut          Cut
weaken       弱化
map          映射
comp         复合
ext          外延
congr        同余
mono         单调
inj          单射
surj         满射
sound        可靠
complete     完备
intro        引入
elim         消去
trans        传递
assoc        结合
id           恒等
```

词根可以由少量短词组成，例如：

```text
subst_wff_m
eval_subst_m
imp_trans_m
all_intro_m
all_elim_m
line_condition_m
certificate_sound_m
```

原则如下：

- 优先使用数学界已经稳定的缩写；
- 优先描述命题对象和数学关系；
- 不把完整参数列表复制进名称；
- 不把当前实现算法、tactic、辅助变量或证明路线写进名称；
- 不使用 `foo`、`bar`、`basic`、`main`、`helper`、`aux`、`tmp`、`new`、`old`、`final`、`v2`；
- 不使用 `by_simp`、`by_cases`、`by_induction` 等证明脚本痕迹；
- 需要增加信息时，先增加一个稳定数学词根，再考虑是否应当拆分接口。

## 三、命名空间与命题名

命名空间负责表达模块归属，命题名负责表达数学意义。

例如：

```text
YesMetaZFC.MF1.Automation.subst_wff_m
YesMetaZFC.MF1.Semantics.sound_m
```

不再重复写成：

```text
mf1_automation_subst_wff_m
mf1_semantics_sound_m
```

如果命名空间已经明确对象类型，命题名不再重复添加低信息量前缀。例如在公式替换模块中优先使用：

```text
subst_wff_m
```

而不是：

```text
formula_substitute_preserves_well_formedness_m
```

只有在同一命名空间内确实存在多个数学对象的同名操作时，才增加一个短限定词：

```text
term_subst_m
formula_subst_m
context_subst_m
```

## 四、局部变量

局部上下文变量统一使用数学意义上的通用单符号。变量名不编码完整类型、模块路径、层级名称或实现角色。

### 4.1 基本符号

| 符号 | 默认含义 |
| --- | --- |
| `κ λ μ` | 基数 |
| `α β γ δ ξ η θ` | 序数 |
| `ℒ` | 语言，纯集合论语言固定使用 `ℒ` |
| `ℳ` | 当前主要结构 |
| `𝒩` | 第二个或目标结构 |
| `𝒱` | 具有 ambient universe 角色的结构 |
| `𝒞` | `OrderedPairConvention` |
| `𝕀` | 解释 |
| `φ ψ χ` | 公式 |
| `s t u` | 项 |
| `Γ Δ Θ` | 理论或上下文 |
| `A B C` | 集合或类 |
| `F G H` | 类函数、schema 或递归算子 |
| `f g` | 函数 |
| `R S` | 关系 |
| `p q` | 证明、子句或其他短对象 |

这些符号的数学性质仍必须由显式假设给出，不能因为变量名而隐含额外假设。

### 4.2 下标

额外信息只使用短下标：

```text
ℒ₀ ℒ₁
ℳ₀ ℳ₁
𝕀₀ 𝕀₁
φ₀ φ₁
Γ₀ Γ₁
```

推荐约定：

- `₀`、`₁`、`₂`：同类对象的区分；
- `ᵢ`、`ⱼ`：任意索引；
- `ₙ`：自然数或递归指标；
- 只有在数学语境已经稳定时，才使用字母下标表示额外角色；
- 不使用长英文下标，例如 `φ_source`、`φ_target`、`ℳ_with_pairing`。

层后缀和局部变量下标是两套不同规则：

- 声明名的 `_l`、`_m`、`_d` 表示命题层级；
- 局部变量的下标只表示同类对象区分或数学索引；
- 局部变量默认不重复声明层级，变量类型已经能够区分时不得增加层下标；
- 只有同一作用域内确实存在同名异层对象时，才允许使用短层下标消歧。

### 4.3 局部假设

局部证明假设也保持数学化：

```text
h
h₁ h₂
hφ
hΓ
hℳ
hZF
hKP
hZFC
```

不使用：

```text
h_formula_is_well_formed
h_target_model_satisfies_zfc
h_source_context_subset
```

已有的结构化假设名 `hZF`、`hKP`、`hZFC`、`hℳZF`、`h𝒩ZF` 等继续遵守仓库既有符号约定。

## 六、迁移规则

命名迁移按完整模块或完整层进行，不保留旧名称兼容别名，不同时维护两套公开接口。

每次迁移遵循以下顺序：

1. 先确定模块的主层级；
2. 建立该模块使用的数学词根表；
3. 先重命名最难、最常被调用的公开定理；
4. 同步修改全部参数名、调用点和导出点；
5. 使用 `lake build` 验证完整项目；
6. 清理旧名称、临时别名和无效兼容层；
7. 完成后再进行一轮数学可读性检查。

迁移过程中不允许：

- 使用 `alias`、兼容 theorem 或桥接定义长期保留旧命名；
- 仅修改表面名称而保留错误的层级归属；
- 通过增加泛化参数、选择公理或虚空假设绕过真实命名迁移；
- 用临时 `smoke` 文件进入正式编译层；
- 为迁移创建无实际复用价值的 helper lemma。

## 七、最低检查标准

一个新的公开证明接口至少必须满足：

- 名称能通过末尾后缀识别所属层；
- 名称中的数学词根与主结论一致；
- 没有证明 tactic 或实现细节；
- 没有重复命名空间信息；
- 局部变量遵守数学单符号约定；
- 额外区分使用短下标，而不是长英文角色名；
- 定理所需参数保持其实际需要的最弱数学强度；
- 名称迁移后没有留下旧接口兼容层。
